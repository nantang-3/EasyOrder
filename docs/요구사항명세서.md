# 음성 주문 키오스크 프로토타입 요구사항명세서

Oct 16, 2026 · @김민철

## 1. 개요

본 문서는 키오스크 버튼 입력부터 손님 주문 음성 인식까지의 요구사항을 정의하며, 개발 완료 목표일은 2026-10-20(화)이다. 미확정 항목은 모두 `확인 필요`로 표기한다.

| 용어 | 정의 |
| --- | --- |
| TTS | Text-To-Speech, 텍스트를 음성으로 출력 |
| STT | Speech-To-Text, 손님 음성을 텍스트로 변환 |
| 식사 방식 | "포장" 또는 "매장" 중 손님이 선택한 값 |
| 세션 | 시작 버튼 터치부터 주문 인식 완료(또는 종료)까지의 한 번의 대화 |
| 시작 버튼 | WPF 화면에 표시되는 대화 시작 터치 버튼 (키오스크 내장 버튼 없음) |
| 메뉴 대분류 | 메뉴를 묶는 상위 분류 (화면 왼쪽에 표시) |

## 2. 대화 흐름 및 상태 정의

한 세션은 S0 대기에서 시작해 S5 주문 인식 완료까지 6개 상태를 순서대로 거친다.

음성 인식 실패 시 "천천히 말해주세요."를 출력하고 같은 상태에서 다시 듣는다(3회 실패 시 터치 주문 안내 음성 출력 후 음성 입력 중단, 화면은 유지). 60초간 터치와 말이 모두 없으면 S0(QR 화면)으로 복귀한다. "주문 완료"를 누르면 주문 완료 화면을 표시한 뒤 S0(QR 화면)으로 복귀한다(FR-19). 화면은 「EasyOrder 키오스크 화면 설계.pdf」를 따른다.

## 3. 기능 요구사항

기능 요구사항은 19건이다. 화면 구성·문구는 「EasyOrder 키오스크 화면 설계.pdf」(이하 화면 설계서)를 따른다.

| ID | 요구사항명 | 상세 내용 | 우선순위 | 확인 필요 사항 |
| --- | --- | --- | --- | --- |
| FR-01 | 화면 터치로 세션 시작 | QR 화면(FR-13)에서 화면 아무 곳이나 터치하면 시작 화면으로 전환한다. 시작 화면은 "폴리텍점 카페 키오스크", "어서 오세요 폴리텍점입니다", "화면을 터치하면 주문을 시작합니다"를 표시하고, 다시 화면 아무 곳이나 터치하면 세션을 시작하고 포장/매장 선택 화면을 표시한다. 포장/매장 선택 화면은 질문 "포장이신가요? 매장에서 드시나요?"와 매장("여기서 먹고 갈게요")·포장("가져갈게요") 버튼, 음성 세션이면 "듣고 있어요 / '포장' 또는 '매장'이라고 말씀해 주세요"와 인식된 말 칸을 표시한다. 휴대폰에서 "음성주문활성화" 버튼을 누르면(FR-14) 시작 화면을 거치지 않고 바로 포장/매장 선택 화면으로 이동한다. 머리글에는 "폴리텍점", 선택된 식사 방식, 단계 표시(1 식사 방식 / 2 메뉴 선택)를 표시한다. | 필수 | - |
| FR-02 | 인사 및 식사 방식 질문 음성 출력 | "음성주문활성화"로 포장/매장 선택 화면으로 이동할 때 "안녕하세요. 폴리텍점입니다. 포장이신가요? 매장에서 드시나요?"를 TTS로 출력한다. 음성 출력은 휴대폰 오디오가 활성화된 경우에만 동작한다(FR-14). | 필수 | 재생 속도·볼륨 (음성: Azure SunHi로 사전 생성한 WAV를 휴대폰에서 재생) |
| FR-03 | 식사 방식 음성 인식 | FR-02 출력 후 손님이 말한 문장에서 "포장" 또는 "매장"을 인식한다. 동의어도 인정한다(포장: 포장, 테이크아웃, 가져갈게요, 가지고 갈게요, 들고 갈게요 / 매장: 매장, 먹고 갈게요, 여기서 먹을게요, 여기서 먹고 갈게요, 매장에서 먹을게요). 문장에 해당 말이 들어 있으면 인정하고(띄어쓰기 무시), 양쪽 말이 모두 들어 있거나 둘 다 없으면 인식 실패로 처리한다. | 필수 | - |
| FR-04 | 식사 방식 저장 | 인식 또는 터치로 선택된 식사 방식을 현재 세션에 보관한다. | 필수 | - |
| FR-05 | 주문 질문 음성 출력 | 식사 방식 인식 후 "무엇을 주문하시겠습니까?"를 TTS로 출력한다. 메뉴 화면 아래에는 "무엇을 주문하시겠습니까? / 메뉴와 수량을 말씀해 주세요"와 인식된 말 칸을 표시한다. | 필수 | - |
| FR-06 | 주문 음성 수신 및 텍스트 변환 | 휴대폰 버튼을 누르면 녹음(음성 인식)을 시작하고, 한 번 더 누르면 녹음을 종료하며 인식된 텍스트를 키오스크로 보낸다. 버튼 문구는 포장/매장 단계에서 "대답하기", 메뉴 단계부터 "주문하기"로 표시한다. | 필수 | - (엔진: 휴대폰 Chrome Web Speech API) |
| FR-07 | 주문 내용 분석 | 변환된 텍스트에서 메뉴명과 수량을 분석한다. 한 문장에 여러 메뉴가 구분되면 모두 인정한다(복수 메뉴 허용). 수량을 말하지 않으면 1잔으로 한다. 메뉴 별칭을 인정한다(라테→라떼, 마키아토→마끼아또, 쥬스→주스, 아메→아메리카노, 녹차라떼→그린티라떼, 녹차→그린티, 홍차라떼→블랙티라떼, 띄어쓰기 무시). 음성 주문 옵션은 분석하지 않고 기본값(HOT · Normal · 샷 기본 · 우유)으로 넣고 "(음성 기본값)"으로 표시한다. 수량 최대값은 999. | 필수 | - |
| FR-08 | 인식 결과 화면 표시 | 분석된 메뉴·수량을 화면 오른쪽 주문 목록에 "음성" 표시와 함께 담고, 인식된 말을 화면 아래 인식된 말 칸에 표시한다. | 필수 | - |
| FR-09 | 인식 실패 처리 | "포장"/"매장" 또는 주문을 인식하지 못하면 "천천히 말해주세요."를 출력하고 다시 듣는다. 질문 단계별로 3회 실패하면 "음성 인식이 어렵습니다. 화면을 터치해서 주문해 주세요."를 음성으로 출력하고, 이후에는 음성 입력을 받지 않고 터치로만 주문한다. 키오스크 화면은 그대로 유지한다. | 필수 | - |
| FR-10 | 무응답 타임아웃 | 세션 중 60초간 터치와 말이 모두 없으면 세션을 초기화하고 초기화면(QR 화면)으로 돌아간다. 머리글 가운데(식사 방식 배지와 단계 표시 사이)에 "남은 시간 n초"를 표시하고, 터치하거나 말하면 60초부터 다시 센다. | 필수 | - |
| FR-11 | 시작페이지로 버튼 | 세션 진행 중 화면 왼쪽 아래의 "시작페이지로" 버튼을 누르면 화면 가운데에 알림 "처음 화면으로 돌아가시겠습니까?"와 "예"/"아니요" 버튼을 표시한다. "예"를 누르면 세션을 초기화하고 QR 화면으로 돌아가며, "아니요"를 누르면 알림만 닫고 현재 화면을 유지한다. | 필수 | - |
| FR-12 | 메뉴 화면 표시 | 왼쪽에 메뉴 대분류, 가운데에 선택한 대분류의 메뉴(개수 표시, 2열, 카드 동그라미에 메뉴 사진), 오른쪽에 주문 목록을 표시한다. 주문 목록은 항목 수, 메뉴명과 음성/터치 표시, 옵션 요약, 수량(− n +), 삭제, 총 수량("n잔"), "주문 완료"·"전체 삭제" 버튼을 표시한다. | 필수 | - |
| FR-13 | 휴대폰 접속 QR 코드 표시 | WPF 앱 시작 시 cloudflared를 자동 실행(로컬 포트 6703 연결)하고, 출력된 HTTPS 주소(trycloudflare.com)를 읽어 QR 코드로 만든다. QR 화면은 "폴리텍점 카페 키오스크", "음성으로 주문하시려면 QR을 찍어 주세요", QR 코드, 3단계 안내(1 휴대폰 카메라로 QR 촬영 / 2 Chrome으로 페이지 열기 / 3 '음성주문활성화' 버튼 누르기), "화면을 터치해 주세요 / 음성 없이 터치로도 주문할 수 있어요"를 표시한다. 화면 터치 시 시작 화면으로 넘어가며, 주문 완료나 시작페이지로 "예"로 대기 화면에 돌아오면 다시 표시한다. | 필수 | - |
| FR-14 | 휴대폰 음성주문 활성화 | 휴대폰 페이지 가운데에 "음성주문활성화" 버튼을 표시한다. 모든 음성 출력(TTS)과 음성 인식(STT)은 휴대폰에서 이 버튼을 누른 경우에만 동작한다. 버튼을 누르면 문구가 "활성화됨"으로 바뀌고 색이 바뀌며, 이후에는 눌러도 반응하지 않는다. | 필수 | 활성화 후 버튼 색 (현재 초록색) |
| FR-15 | 터치 주문 | "음성주문활성화" 버튼을 누르지 않은 모든 경우(QR 미접속 포함) 터치로만 주문을 진행한다. 포장/매장 버튼을 터치해 식사 방식을 선택하고, 메뉴를 터치하면 옵션 팝업을 띄운다. 팝업은 메뉴 사진(사용자 제공 사진을 400×400으로 줄여 Images/Menu/{메뉴 id}.png로 사용, 없으면 자리표시), 대분류·메뉴명, 해당 옵션 그룹(라떼는 온도·사이즈·샷 조절·우유 변경, 사이즈는 Normal·Large 순서, 칸 안에서 스크롤로 나열, 선택한 칸은 색 변경), 수량(− 1 +, 기본 1, 최대 999, 숫자 칸 터치 시 앱 내 숫자 키패드), "취소"·"주문 목록에 담기" 버튼을 표시한다. 온도·사이즈를 고르지 않으면 "주문 목록에 담기"가 활성화되지 않는다. 주문 목록에는 "터치" 표시로 담긴다. | 필수 | - |
| FR-16 | 휴대폰 대답하기 버튼·듣는 중 표시 | "음성주문활성화"를 눌러 "활성화됨"으로 바뀐 뒤, 그 아래에 "대답하기"(메뉴 단계부터 "주문하기") 버튼을 표시하고 버튼 왼쪽에 마이크 모양 이미지를 둔다. 녹음 중에는 마이크 주변에 빨간빛이 살짝 반짝여 듣는 중임을 표시한다. | 필수 | - |
| FR-17 | 음성 주문 확인 멘트·취소 | 음성 주문을 주문 목록에 담은 뒤 "(메뉴) (수량) 맞습니까? 아니라면 취소라고 주문하기 버튼을 누르고 말해주세요. 다른메뉴 추가 주문하시면 주문하기버튼을 누르고 주문해주세요. 주문을 마치시려면 주문하기 버튼을 누르고 주문완료라고 말해주세요."를 출력한다. 여러 메뉴면 "아메리카노 한 잔, 카페라떼 두 잔 맞습니까? …"처럼 이어서 읽는다. 멘트는 메뉴·수량에 따라 달라지므로 실행 중 Azure TTS(SunHi)로 만들어 휴대폰에서 재생하며, Azure로 만들지 못하면 Windows 내장 음성(한국어)으로 대신 만든다. 손님이 "취소"라고 말하면 바로 전에 음성으로 담은 메뉴(묶음)를 주문 목록에서 빼고 "취소되었습니다. 다시 주문해주세요"를 출력한다(사전 생성 WAV). | 필수 | - |
| FR-18 | 전체 삭제 확인 | "전체 삭제"를 누르면 화면 가운데에 "메뉴 전체를 삭제시킵니다. 정말로 하시겠습니까?" 알림과 예/아니요를 표시하고, 예를 누르면 주문 목록을 모두 비운다. | 필수 | - |
| FR-19 | 주문 완료 | "주문 완료"를 누르거나, 음성 세션에서 주문하기 버튼을 누르고 "주문완료"라고 말하면(주문 목록이 비어 있으면 인식 실패 처리) "주문이 완료되었습니다." 화면을 띄우고, 남은 초(30초부터 1초씩 줄어듦)를 시작페이지로 버튼 위에 표시하고, 30초가 지나면 자동으로 세션을 초기화하고 QR 화면으로 돌아간다. 완료 화면에는 "시작페이지로" 버튼을 두어 누르면 바로 QR 화면으로 돌아간다(결제·POS 연동 없음). | 필수 | - |

## 4. 비기능 요구사항

비기능 요구사항의 목표 수치는 아직 제시된 것이 없어 항목만 정의하고 기준값은 확인 필요로 둔다.

| ID | 항목 | 요구 내용 | 기준값 |
| --- | --- | --- | --- |
| NFR-01 | 플랫폼 | WPF 기반 Windows 데스크톱 애플리케이션으로 동작한다. | C# / .NET 10 (SDK 10.0.401), Windows 세부 버전: 확정: Windows 10 (키오스크 PC) |
| NFR-02 | 언어 | 한국어 음성 출력 및 인식 | 다국어 지원: 해당 없음 (이번 범위 제외, 추후 필요 시 확장) |
| NFR-03 | 응답 시간 | 손님 발화 종료 후 다음 안내 음성까지의 지연 | 확정: 5초 이내 |
| NFR-04 | 인식 정확도 | "포장"/"매장" 및 주문 인식률 | 확정: 90% 이상 |
