# 음성 주문 키오스크 프로토타입 요구사항명세서

Oct 16, 2026 · @김민철

## 1. 개요

본 문서는 키오스크 버튼 입력부터 손님 주문 음성 인식까지의 요구사항을 정의하며, 개발 완료 목표일은 2026-10-20(화)이다. 미확정 항목은 모두 `확인 필요`로 표기한다.

| 용어 | 정의 |
| --- | --- |
| TTS | Text-To-Speech, 텍스트를 음성으로 출력 |
| STT | Speech-To-Text, 손님 음성을 텍스트로 변환 |
| 식사 방식 | "포장" 또는 "매장" 중 손님이 선택한 값 |
| 세션 | 시작 버튼 터치부터 주문 인식 완료(또는 종료)까지의 한 번의 대화 |
| 시작 버튼 | WPF 화면에 표시되는 대화 시작 터치 버튼 (키오스크 내장 버튼 없음) |
| 메뉴 대분류 | 메뉴를 묶는 상위 분류 (화면 왼쪽에 표시) |

## 2. 대화 흐름 및 상태 정의

한 세션은 S0 대기에서 시작해 S5 주문 인식 완료까지 6개 상태를 순서대로 거친다.

S5 이후 S0으로 복귀하는 시점과, 실패·무응답 시 어느 상태로 돌아갈지는 확인 필요다.

## 3. 기능 요구사항

기능 요구사항은 13건이며, FR-09\~FR-11은 세부 정책이 모두 확인 필요다.

| ID | 요구사항명 | 상세 내용 | 우선순위 | 확인 필요 사항 |
| --- | --- | --- | --- | --- |
| FR-01 | 시작 버튼 터치 감지 | 대기 상태에서 화면의 시작 버튼을 터치하면 세션을 시작한다. | 필수 | 시작 버튼 위치·문구 |
| FR-02 | 인사 및 식사 방식 질문 음성 출력 | "안녕하세요. 폴리텍점입니다. 포장이신가요? 매장에서 드시나요?"를 TTS로 출력한다. | 필수 | 재생 속도·볼륨 (음성: Azure SunHi로 사전 생성한 WAV를 휴대폰에서 재생) |
| FR-03 | 식사 방식 음성 인식 | FR-02 출력 완료 후 음성을 수신하여 "포장" 또는 "매장"을 인식한다. | 필수 | 동의어 허용 여부(예: "테이크아웃", "먹고 갈게요") |
| FR-04 | 식사 방식 저장 | 인식된 식사 방식을 현재 세션에 보관한다. | 필수 | - |
| FR-05 | 주문 질문 음성 출력 | 식사 방식 인식 후 "무엇을 주문하시겠습니까?"를 TTS로 출력한다. | 필수 | - |
| FR-06 | 주문 음성 수신 및 텍스트 변환 | FR-05 출력 완료 후 손님 음성을 STT로 텍스트 변환한다. | 필수 | 발화 종료 판단 방식 (엔진: 휴대폰 Chrome Web Speech API) |
| FR-07 | 주문 내용 분석 | 변환된 텍스트에서 메뉴명과 수량을 분석한다. (완료 기준: 메뉴·수량 분석까지) | 필수 | 옵션은 음성 분석 제외(추후 추가), 복수 메뉴 허용 여부, 수량 미발화 시 기본값 |
| FR-08 | 인식 결과 화면 표시 | 분석된 메뉴·수량을 화면 오른쪽 주문 목록에 표시한다. | 필수 | 식사 방식 표시 위치, 인식 결과 음성 복창 여부 |
| FR-09 | 인식 실패 처리 | "포장"/"매장" 또는 주문을 인식하지 못한 경우의 동작 | 확인 필요 | 재질문 멘트, 재시도 횟수, 초과 시 동작 |
| FR-10 | 무응답 타임아웃 | 손님이 일정 시간 말하지 않는 경우의 동작 | 확인 필요 | 대기 시간(초), 타임아웃 후 처리 |
| FR-11 | 진행 중 시작 버튼 재터치 처리 | 세션 진행 중 시작 버튼이 다시 터치된 경우의 동작 | 확인 필요 | 무시 / 처음부터 재시작 / 기타 |
| FR-12 | 메뉴 화면 표시 | 왼쪽에 메뉴 대분류, 가운데에 선택한 대분류에 속한 메뉴, 오른쪽에 주문 목록을 표시한다. | 필수 | 메뉴 터치로도 주문 담기 허용 여부, 세부 디자인 |
| FR-13 | 휴대폰 접속 QR 코드 표시 | WPF 앱 시작 시 cloudflared를 자동 실행(로컬 포트 6703 연결)하고, 출력된 HTTPS 주소(trycloudflare.com)를 읽어 QR 코드로 만든다. QR은 대기 화면에 상시 표시하고 화면 터치가 발생하면 숨기며, 주문 세션이 끝나 대기 화면으로 돌아오면 다시 표시한다. 휴대폰은 QR을 찍어 접속한다. | 필수 | QR 표시 위치 |

## 5. 인터페이스 요구사항

외부와 연결되는 접점은 버튼, 마이크, 스피커, 화면 4가지이며, POS 등 외부 서버 연동은 없다.

| ID | 구분 | 내용 | 확인 필요 사항 |
| --- | --- | --- | --- |
| IR-01 | 입력 - 시작 버튼 | WPF 화면 터치로 세션 시작 (내장 버튼 없음) | 터치스크린 장비 유무 (없으면 마우스 클릭으로 테스트) |
| IR-02 | 하드웨어 - 마이크 | 휴대폰 브라우저 웹페이지에서 마이크 사용 | Galaxy S26 Ultra (Android) Chrome 사용으로 확정 |
| IR-03 | 하드웨어 - 스피커 | 휴대폰 웹페이지에서 안내 음성 WAV 재생 | 자동 재생 허용을 위한 최초 1회 터치 위치 |
| IR-04 | 소프트웨어 - TTS | Azure Speech TTS(F0, ko-KR SunHi)로 안내 문구 2종 WAV 사전 생성 (대체: Windows 내장 TTS) | - |
| IR-05 | 소프트웨어 - STT | 휴대폰 Chrome Web Speech API로 인식하고 텍스트만 PC로 전송 | 인식 언어 ko-KR, 중간 결과 사용 여부 |
| IR-06 | 사용자 화면 - WPF | 좌: 메뉴 대분류 / 중: 소속 메뉴 / 우: 주문 목록, 시작 버튼 및 안내 문구 표시 | 시작 버튼·안내 문구·듣기 중 표시 위치, 해상도, 디자인 시안 |
| IR-07 | 데이터 저장 | 메뉴 데이터는 JSON 파일 (MySQL은 추후 필요 시) | - |
| IR-08 | PC-휴대폰 통신 | WPF 앱 내장 로컬 웹서버가 휴대폰 페이지를 제공하고, WebSocket으로 재생 명령(PC→휴대폰)과 인식 텍스트(휴대폰→PC)를 주고받음 | HTTPS는 Cloudflare Quick Tunnel + QR 접속으로 확정(FR-13), 로컬 포트 6703 (http://localhost:6703) |

화면은 3단 구성(대분류 / 소속 메뉴 / 주문 목록)으로 확정되었으며, 대기·듣기 중 상태를 어디에 표시할지는 확인 필요다.

## 6. 데이터 요구사항

세션 동안 다루는 데이터는 식사 방식과 주문 인식 결과이며, 메뉴 데이터의 항목과 출처는 확인 필요다.

| ID | 데이터 | 항목 | 비고 |
| --- | --- | --- | --- |
| DR-01 | 세션 정보 | 세션 식별자, 시작 시각, 현재 상태 | 메모리 보관, 영구 저장 여부 확인 필요 |
| DR-02 | 식사 방식 | 포장 / 매장 | 2개 값 고정 |
| DR-03 | 주문 인식 원문 | STT 변환 텍스트 | - |
| DR-04 | 주문 해석 결과 | 메뉴명, 수량, 옵션 | 메뉴명·수량 (옵션은 음성 분석 제외, 추후 추가) |
| DR-05 | 메뉴 데이터 | 대분류, 메뉴명, 별칭, 옵션 등 | 6.1 메뉴 데이터 참고, 저장 형식은 JSON 파일 (MySQL은 추후 필요 시) |

가격 정보는 결제가 제외 범위이므로 필요 여부가 확인 필요다.

### 6.1 메뉴 데이터

카페용 메뉴는 5개 대분류, 26개 메뉴로 구성한다.

| 대분류 | 메뉴 | 개수 |
| --- | --- | --- |
| 커피 | 아메리카노, 에스프레소, 카푸치노, 카페모카, 카라멜마끼아또, 아포가토 | 6 |
| 라떼 | 카페라떼, 그린티라떼, 블랙티라떼, 오곡라떼, 팥라떼, 쑥라떼, 고구마라떼, 바닐라라떼 | 8 |
| 에이드 | 자몽에이드, 청포도에이드 | 2 |
| 주스 | 오렌지주스, 자몽주스, 포도주스, 사과주스, 파인애플주스 | 5 |
| 차(Tea) | 그린티, 허브티, 밀크티, 아이스티, 페퍼민트티 | 5 |

| 대분류 | 온도 | 사이즈 | 추가 옵션 |
| --- | --- | --- | --- |
| 커피 | HOT / ICE | Large / Normal | 샷 조절: 아주 연하게(-3), 연하게(-2), 살짝 연하게(-1), 기본, 샷추가 +1\~+4 (최대 4회) |
| 라떼 | HOT / ICE | Large / Normal | 우유 변경: 우유(기본), 두유, 아몬드 브리즈, 오트음료 |
| 에이드 | HOT / ICE | Large / Normal | - |
| 주스 | HOT / ICE | Large / Normal | - |
| 차(Tea) | HOT / ICE | Large / Normal | - |

옵션은 화면 주문용 데이터로만 정의하며, 음성 주문의 옵션 분석은 이번 범위에서 제외하고 추후 추가한다.

메뉴 JSON 구조는 아래와 같으며, 나머지 대분류도 같은 형식으로 작성한다.

```json
{
  "store": "폴리텍점",
  "optionGroups": [
    { "id": "temp", "name": "온도", "choices": ["HOT", "ICE"] },
    { "id": "size", "name": "사이즈", "choices": ["Large", "Normal"] },
    { "id": "shot", "name": "샷 조절", "default": 0, "choices": [
      { "label": "아주 연하게", "value": -3 },
      { "label": "연하게", "value": -2 },
      { "label": "살짝 연하게", "value": -1 },
      { "label": "기본", "value": 0 },
      { "label": "샷추가 1회", "value": 1 },
      { "label": "샷추가 2회", "value": 2 },
      { "label": "샷추가 3회", "value": 3 },
      { "label": "샷추가 4회", "value": 4 }
    ] },
    { "id": "milk", "name": "우유 변경", "default": "우유", "choices": ["우유", "두유", "아몬드 브리즈", "오트음료"] }
  ],
  "categories": [
    {
      "id": "coffee",
      "name": "커피",
      "optionGroups": ["temp", "size", "shot"],
      "menus": [
        { "id": "americano", "name": "아메리카노", "aliases": [] },
        { "id": "espresso", "name": "에스프레소", "aliases": [] },
        { "id": "cappuccino", "name": "카푸치노", "aliases": [] },
        { "id": "cafe-mocha", "name": "카페모카", "aliases": [] },
        { "id": "caramel-macchiato", "name": "카라멜마끼아또", "aliases": [] },
        { "id": "affogato", "name": "아포가토", "aliases": [] }
      ]
    }
  ]
}
```

`aliases`는 음성 인식용 별칭 자리이며, 등록할 별칭은 확인 필요다. 메뉴 데이터 관련 확인 필요 항목은 다음과 같다.

- 라떼 HOT/ICE·사이즈 옵션 적용 (확정, 우유 기본값은 "우유")
- 메뉴별 음성 별칭(aliases) 등록 대상

## 7. 제외 범위 및 제약사항

다음 7개 항목은 이번 개발 범위에서 제외하며 관련 요구사항을 정의하지 않는다.

- 실제 결제
- POS 주문 서버 연동
- 매장 주문 접수
- 회원 관리
- 쿠폰 관리
- 재고 관리
- 운영 배포

**제약사항**

- 개발 인원 1명, 개발 기간 2026-10-16 \~ 2026-10-20 21시경 (주말 포함)
- 화면은 WPF(C#, .NET 10)로 구현, 마이크·스피커는 휴대폰 사용, TTS는 Azure로 사전 생성한 WAV, STT는 휴대폰 Chrome Web Speech API 사용(모두 무료), PC에는 마이크·스피커 없음
- 안내 문구 2종은 사용자가 제시한 문장을 그대로 사용 (매장명: 폴리텍점)
