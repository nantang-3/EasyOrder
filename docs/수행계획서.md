# 음성 주문 키오스크 프로토타입 수행계획서

Oct 16, 2026 · @김민철

## 1. 사업 개요

2026-10-20(화)까지 1인 개발로, 키오스크 버튼 입력부터 손님의 음성 주문 인식까지 동작하는 WPF 기반 프로토타입을 완성한다.

| 항목 | 내용 |
| --- | --- |
| 프로젝트명 | EasyOrder (음성 주문 키오스크 프로토타입, GitHub 저장소명 기준) |
| 목적 | 키오스크에서 음성 안내(TTS)와 음성 인식(STT)으로 식사 방식 선택 및 주문 접수 흐름을 검증 |
| 수행 기간 | 2026-10-16(금) \~ 2026-10-20(화), 5일 |
| 수행 인원 | 1명 (풀스택 개발자) |
| 적용 매장 | 폴리텍점 |
| 배포 URL | 해당 없음 (운영 배포 제외) |

목표 대화 흐름은 다음과 같다.

1. 손님이 키오스크 화면의 시작 버튼을 터치한다.
2. 키오스크가 "안녕하세요. 폴리텍점입니다. 포장이신가요? 매장에서 드시나요?"를 음성으로 출력한다.
3. 손님이 "포장" 또는 "매장"이라고 말한다.
4. 키오스크가 "무엇을 주문하시겠습니까?"를 음성으로 출력한다.
5. 손님이 주문을 말하고, 키오스크가 이를 인식한다.

## 2. 수행 범위

이번 기간에는 버튼 입력 → 음성 안내 → 식사 방식 인식 → 주문 질문 → 주문 인식까지만 개발하며, 결제·연동·운영 기능은 제외한다.

**포함 범위**

| 번호 | 항목 | 비고 |
| --- | --- | --- |
| 1 | 화면 터치 시작 버튼 입력 감지 | 내장 버튼 없음, 화면 터치로 대체 |
| 2 | 인사 및 식사 방식 질문 음성 출력(TTS) | 매장명: 폴리텍점 |
| 3 | "포장" / "매장" 음성 인식(STT) | 동의어 허용 범위 확인 필요 |
| 4 | 주문 질문 음성 출력(TTS) | - |
| 5 | 손님 주문 음성 인식 | 완료 기준: 메뉴·수량 분석까지 |
| 6 | WPF 화면 출력 | 좌: 메뉴 대분류 / 중: 소속 메뉴 / 우: 주문 목록 |
| 7 | 터치 주문 | "음성주문활성화"를 누르지 않은 경우 포장/매장·메뉴를 터치로 선택 |

**제외 범위**

| 번호 | 항목 |
| --- | --- |
| 1 | 실제 결제 |
| 2 | POS 주문 서버 연동 |
| 3 | 매장 주문 접수 |
| 4 | 회원 관리 |
| 5 | 쿠폰 관리 |
| 6 | 재고 관리 |
| 7 | 운영 배포 |

주문 인식 이후 단계(주문 확인 멘트, 추가 주문 질문 등)의 포함 여부: 확인 필요

## 4. 기술 스택 및 개발 환경

기술 스택은 키오스크 Windows 세부 버전을 제외하고 모두 확정되었다.

| 구분 | 내용 | 상태 |
| --- | --- | --- |
| Frontend (화면) | WPF | 확정 |
| 개발 언어 | C# (.NET 10 기본 버전인 C# 14) | 확정 |
| .NET | .NET 10 (SDK 10.0.401), 대상 프레임워크 net10.0-windows | 확정 |
| 음성 합성(TTS) | Azure Speech TTS(F0, ko-KR SunHi)로 안내 음성 5종을 WAV로 사전 생성하여 재생, 주문 확인 멘트는 실행 중 생성. 대체 수단: Windows 내장 TTS | 확정 |
| 음성 인식(STT) | 휴대폰 Chrome Web Speech API (휴대폰 웹페이지에서 인식 후 텍스트만 WPF로 전송) | 확정 |
| 마이크 / 스피커 | 휴대폰 (브라우저 웹페이지로 연결, PC에는 마이크·스피커 없음) | 확정 |
| PC-휴대폰 통신 | WPF 앱 내장 로컬 웹서버(휴대폰 페이지 제공) + WebSocket, HTTPS는 Cloudflare Quick Tunnel 주소를 WPF 화면 QR 코드로 접속, 로컬 포트 6703 | 확정 |
| 인터넷 연결 | 필요 (Web Speech API 온라인 인식, WAV 생성 시 Azure 호출) | 확정 |
| Database | JSON 파일 (MySQL은 추후 필요 시 도입) | 확정 |
| 키오스크 OS | Windows (세부 버전 확인 필요, Windows 11 검토 중) | 부분 확정 |
| 휴대폰 OS / 브라우저 | Galaxy S26 Ultra (Android), Chrome 브라우저 | 확정 |
| 시작 입력 | 화면 터치 버튼 (내장 버튼 없음) | 확정 |
| 형상관리 | Git / [GitHub 저장소](https://github.com/nantang-3/EasyOrder.git), GitHub Flow | 확정 |
| Infrastructure | 해당 없음 (운영 배포 제외) | 확정 |

## 8. 위험 관리

가장 큰 위험은 휴대폰 웹페이지를 통한 음성 입출력 연결(HTTPS 마이크 권한, 네트워크)이다.

| 위험 | 영향 | 대응 방안 |
| --- | --- | --- |
| 휴대폰 브라우저 마이크 권한은 HTTPS(보안 컨텍스트)에서만 허용 | 휴대폰에서 음성 인식 불가 | Cloudflare Quick Tunnel HTTPS 주소를 QR 코드로 접속(터널 장애·지연 시 USB adb reverse로 대체), 10/17 연결 시험을 최우선 진행 |
| 브라우저 자동 재생 제한 | 휴대폰에서 안내 음성 미재생 | 휴대폰 페이지 접속 시 1회 터치로 오디오 활성화 |
| PC-휴대폰 네트워크 연결 | WebSocket 연결 불가 | 같은 Wi-Fi 사용, Windows 방화벽 포트 허용 |
| Web Speech API의 인터넷 의존 및 브라우저별 지원 차이 | 인식 중단 | Galaxy S26 Ultra Chrome으로 10/18 전 사전 검증, 대체 수단 Azure STT(F0) |
| 매장 소음 등으로 인식률 저하 | 주문 인식 실패 | "천천히 말해주세요." 출력 후 재청취, 3회 실패 시 터치 주문 안내 (목표 인식률은 확인 필요) |
| 메뉴 데이터 미제공 | 메뉴·수량 분석 및 화면 구성 불가 | 메뉴 데이터 수신 완료(10/16) (요구사항명세서 6.1 반영) |
